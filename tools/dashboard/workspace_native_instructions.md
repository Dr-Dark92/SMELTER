# SMELTER workspace continuity

Before coding or debugging, use `smelter_coding_workspace_context` with no arguments to recover owned workspace IDs and canonical host roots. Reuse the exact ID belonging to this task. With that ID, search/query the persistent filename/SHA-256 index. Never select by newest timestamp or guess duplicate paths. The coding copy is a real host directory; Docker executes read-only test snapshots. The original checkout and Melty working directory are separate locations.

Read exact indexed relative paths through SMELTER. For line reads use `start_line` and `line_count`; `offset` and `limit` are character units. Inspect the actual Lua/Python exports and return values instead of inventing APIs. A missing path calls for an index query, not a recreated file at another root. Use current destination hashes in reviewed proposals.

Load the `diagrams` skill for file relationships and task handoffs. Refresh the exact workspace context after changes/tests and at the end of a coding task. Summarize changed paths, hashes, current/stale test evidence and the relation chart saved as `relations.mmd`. Static/inferred imports are not proof of behavior coverage. Do not claim native Melty chat progress or generated media has been mirrored unless the bridge supplies a real receipt.
